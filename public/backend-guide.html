NUTRI KIDS BACKEND

상품을 찾고,
영양을 계산하는 서버

React가 상품과 사용자 정보를 JSON으로 보내면 FastAPI가 요청 형식을 검증하고 같은 JSON 응답 계약을 유지합니다. 한 끼 판정과 추천 알고리즘은 협업 담당자가 설계할 수 있도록 비워둔 상태입니다.

FastAPI 문서 열기 프론트 화면으로 돌아가기

OVERVIEW

백엔드가 맡는 일

프론트는 입력과 표시를 담당하고, 백엔드는 데이터 조회와 계산 규칙을 한곳에서 관리합니다.

3단계데이터 품질식약처 확인, 국가표준 추정, 미확인
미구현영양 판정과 추천JSON 계약만 유지한 인수인계 상태

REQUEST FLOW

요청 한 번이 처리되는 과정

1

React 요청

프로필과 담은 상품을 JSON으로 전송

2

FastAPI 검증

필드, 나이, 섭취량, 단위를 검사

3

DB 조회

상품과 영양성분, 출처 상태를 조회

4

임시 엔진

상품 존재 여부만 확인하고 미구현 상태 생성

5

JSON 응답

UNKNOWN 판정과 구현 예정 경고를 반환

DATA SOURCES

CU 상품과 공공데이터 결합

값을 임의로 채우지 않고 출처별 신뢰 수준을 응답에 함께 전달합니다.

CONFIRMED

식약처 확인값

  • API에서 확인된 품목제조보고번호만 확정값으로 저장
  • API의 기준량을 실제 판매 용량으로 환산
  • 현재 바나나킥의 열량, 단백질, 나트륨에 적용
ESTIMATED

국가표준 추정값

  • 상품명 별칭과 CU 분류를 정규화해 대표 식품 연결
  • 100g 기준값을 상품 제공량으로 환산
  • 용량이 없으면 100g 또는 100ml 기준으로 표시
MISSING

미확인값

  • 1,092개 상품은 첫 번째 유사 번호를 자동 확정
  • 번호가 있어도 영양값이 없으면 0으로 바꾸지 않음
  • 해당 영양소 판정은 UNKNOWN으로 보류

DATA PIPELINE

원천 파일이 영양값이 되는 과정

대표 번호, 표준식품 연결, 제공량 환산과 출처 우선순위를 단계별로 적용합니다.

1

CU 상품 적재

상품 ID, 이름, 가격, 이미지, 바코드와 번호 후보를 저장

2

상품명 정규화

제조사와 용량을 분리하고 별칭과 특수문자를 통일

3

표준식품 연결

정규화된 이름과 CU 분류로 국가표준 대표 식품 선택

4

기준량 환산

100g 기준값을 판매 용량 또는 표준 100g 기준으로 계산

5

출처 병합

식약처 확인값을 우선하고 없는 성분은 국가표준값 사용

6

API 반환

영양값, 품질, 출처, 연결 식품과 신뢰도를 JSON으로 반환

API

프론트가 호출하는 주소

ALGORITHM

영양 로직 인수인계 상태

1
JSON 계약만 고정

요청과 응답 스키마 외에는 미리 정한 코드 구조가 없습니다.

2
내부 설계는 자유

계산 방식, 파일 구성과 내부 자료형은 담당자가 결정합니다.

3
임시 엔진 교체 가능

공개 함수의 입출력만 유지하면 engine.py도 자유롭게 변경할 수 있습니다.

targetnull
statusUNKNOWN
qualityMISSING
recommendations빈 배열
warningsNUTRITION_ENGINE_PENDING

CURRENT LIMITS

현재 단계에서 알아둘 점

공모전 프로토타입 기준입니다

현재 표준식품 연결은 자동 규칙 기반 추정입니다. 용량이 없는 상품은 100g 또는 100ml 기준이며, 음료는 간이 환산을 사용합니다. 낮은 신뢰도의 분류 기본값은 검토가 필요합니다. 키와 몸무게는 요청에 포함되지만 현재 목표표는 성별, 나이, 식사 횟수를 사용합니다. 회원 인증, 식사 영구 저장, 하루 평가는 다음 구현 범위입니다.

든든 백엔드 설명서, FastAPI + SQLAlchemy + SQLite 또는 MySQL
