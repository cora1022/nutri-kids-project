# 데이터 처리 과정

이 문서는 CU 상품 목록, 품목제조보고번호 후보, 국가표준식품성분표, 식약처 영양성분 API가 검색과 한 끼 분석 데이터로 변환되는 과정을 설명합니다.

## 1. 원천 데이터

### CU 상품 목록

CU 상품 파일에서 다음 값을 읽습니다.

| 원천 항목 | 저장 목적 |
| --- | --- |
| 분류 | 상품 유형별 표준식품 연결 범위 제한 |
| 상품명 | 검색, 제조사 분리, 식품명 정규화, 용량 추출 |
| 가격 | 식사 금액 합산 |
| CU 상품 ID | `cu:{상품 ID}` 형식의 내부 식별자 생성 |
| 이미지 URL | 상품 이미지와 바코드 추출 |
| 품목제조보고번호 후보 | 대표 번호 자동 선택과 후보 이력 보존 |
| 대조 상태와 근거 | 번호가 선택된 과정을 API 응답에 표시 |

이미지 URL 끝에 13자리 숫자가 있으면 바코드로 사용합니다. 같은 바코드가 여러 상품에 반복되면 첫 번째 상품만 바코드를 보유하고 나머지는 `null`로 저장합니다.

### 국가표준식품성분표 10.4

국가표준식품성분표의 값은 가식부 100g 기준입니다. 현재 서비스는 다음 7개 영양소를 사용합니다.

| 영양소 | 원천 열 | 단위 |
| --- | --- | --- |
| 열량 | F열 | kcal |
| 단백질 | H열 | g |
| 칼슘 | V열 | mg |
| 철 | W열 | mg |
| 나트륨 | AA열 | mg |
| 비타민 A | AH열 | µgRAE |
| 비타민 C | AY열 | mg |

빈 셀, `-`, `N/A`, `Tr`은 숫자 0으로 바꾸지 않고 미확인 값으로 처리합니다.

### 식약처 영양성분 API

식약처 API는 제품명과 제조업체로 조회합니다. 현재 직접 확인된 상품은 API 기준량과 품목제조보고번호를 함께 저장합니다. API가 제공하는 영양소는 국가표준 추정값보다 우선합니다.

## 2. CU 상품 적재

모든 CU 상품을 `foods` 테이블에 저장합니다. 검색 API는 이 중 `item_report_no`가 있는 상품만 반환합니다.

품목제조보고번호 후보가 여러 개면 첫 번째 후보를 대표 번호로 선택합니다. 전체 후보는 `item_report_candidates`에 그대로 보존합니다.

| 저장 필드 | 의미 |
| --- | --- |
| `item_report_no` | 검색과 연결에 사용하는 대표 번호 |
| `item_report_candidates` | 원본 파일의 전체 후보 번호 |
| `item_report_status` | 식약처 확인 또는 상품명 유사 자동 확정 |
| `item_report_evidence` | 후보 검색 근거와 대표 번호 선택 방식 |

상품명 유사 자동 확정은 서비스 내부 연결 규칙입니다. 포장지나 제조업체 자료로 확인한 행정상 확정값을 의미하지 않습니다.

## 3. 상품명 정규화

`standard_foods.py`가 상품명을 비교 가능한 형태로 변환합니다.

1. 유니코드를 NFKC 형식으로 통일합니다.
2. `농심)`과 같은 앞쪽 제조사 표기를 제거합니다.
3. `75g`, `300ml`, `1.5L` 같은 용량을 상품명에서 분리합니다.
4. 공백과 특수문자를 제거합니다.
5. 같은 뜻의 표현을 하나의 용어로 바꿉니다.

별칭 정규화 예시는 다음과 같습니다.

| 원래 표현 | 정규화 표현 |
| --- | --- |
| 요거트 | 요구르트 |
| 돈까스 | 돈가스 |
| 오뎅 | 어묵 |
| 도너츠 | 도넛 |
| 핫바, 맥스봉 | 어육소시지 |
| 스파게티 | 파스타 |

## 4. 국가표준식품 연결

정규화된 상품명과 CU 분류를 함께 사용합니다. 구체적인 식품 규칙을 먼저 적용하고, 적용 가능한 규칙이 없으면 일부 분류에 한해 대표 식품 기본값을 사용합니다.

예시는 다음과 같습니다.

| CU 상품 표현 | 국가표준 대표 식품 |
| --- | --- |
| 참깨라면, 사발면, 짬뽕 | 라면, 조리전 |
| 햇반, 컵반 | 멥쌀, 백미, 밥 |
| 햄버거, 버거 | 햄버거, 소고기패티, 채소 포함 |
| 딸기우유 | 우유, 가공우유, 딸기맛 |
| 두유 | 두유, 대두 |
| 쿠키 | 과자, 쿠키, 버터 |
| 감자칩, 포카칩 | 감자 과자, 감자칩, 튀긴것 |
| 아이스크림 상품 | 아이스크림, 유지방 8% |

연결 결과는 `product_standard_mappings` 테이블에 저장합니다.

| 필드 | 의미 |
| --- | --- |
| `standard_food_code` | 국가표준식품성분표 코드 |
| `match_method` | `NORMALIZED_RULE` 또는 `CATEGORY_DEFAULT` |
| `confidence` | 규칙별 연결 신뢰도 |
| `review_status` | 현재 자동 연결 상태인 `AUTO_MATCHED` |

`CATEGORY_DEFAULT`는 상품명만으로 세부 유형을 찾지 못했을 때 사용하는 낮은 신뢰도 연결입니다. 운영 전에는 신뢰도 0.7 미만 항목을 우선 검토해야 합니다.

## 5. 판매 용량 정규화

상품명에서 마지막 용량 표현을 찾습니다.

- `kg`는 `g`으로 변환합니다.
- `L`는 `ml`로 변환합니다.
- 상품명에 용량이 있으면 `상품 기준 추정`으로 표시합니다.
- 용량이 없으면 식품은 100g, 음료는 100ml 기준으로 표시합니다.

국가표준식품성분표는 100g 기준이므로 음료의 ml 환산은 밀도를 1에 가깝다고 보는 간이 추정입니다. 밀도가 중요한 농축액과 시럽은 별도 검토가 필요합니다.

## 6. 영양값 계산

국가표준식품의 100g 기준값은 다음 공식으로 상품 기준값으로 바꿉니다.

```text
상품 영양값 = 국가표준 100g 영양값 × 상품 기준량 ÷ 100
```

예를 들어 국가표준 열량이 408kcal이고 상품 용량이 50g이면 다음과 같이 계산합니다.

```text
408 × 50 ÷ 100 = 204kcal
```

영양소마다 다음 우선순위를 적용합니다.

1. 식약처 API에서 확인된 값
2. 국가표준식품성분표 추정값
3. 미확인값

식약처 API에 열량, 단백질, 나트륨만 있고 국가표준식품에 나머지 영양소가 있으면 한 상품 안에서 두 출처가 함께 사용될 수 있습니다.

## 7. 데이터 품질 표시

| 품질 | 조건 |
| --- | --- |
| `CONFIRMED` | 식약처 API에서 확인된 영양소 |
| `ESTIMATED` | 국가표준식품성분표로 환산한 영양소 |
| `MIXED` | 확인값과 추정값이 함께 있거나 일부 값이 누락된 경우 |
| `MISSING` | 사용할 수 있는 영양값이 없는 경우 |

미확인 영양소는 0으로 바꾸지 않습니다. 선택한 음식 중 하나라도 해당 영양소가 없으면 한 끼 판정은 `UNKNOWN`으로 보류합니다.

## 8. DB 저장 구조

```text
foods
  ├─ food_nutrients
  └─ product_standard_mappings
       └─ standard_foods
```

- `foods`는 CU 상품, 가격, 바코드, 대표 번호와 제공량을 저장합니다.
- `food_nutrients`는 영양소별 값, 단위, 품질과 출처를 저장합니다.
- `standard_foods`는 국가표준식품의 100g 기준값을 저장합니다.
- `product_standard_mappings`는 CU 상품과 국가표준식품의 연결 근거를 저장합니다.

## 9. API 응답

상품 검색과 상세 응답에는 다음 정보가 함께 포함됩니다.

```json
{
  "itemReportNo": "20200450031737",
  "serving": {
    "amount": 100,
    "unit": "g",
    "label": "100g 표준 기준 추정"
  },
  "nutrients": {
    "kcal": {
      "value": 416,
      "unit": "kcal",
      "quality": "ESTIMATED",
      "source": "NATIONAL_STANDARD"
    }
  },
  "standardFoodMatch": {
    "foodCode": "3142",
    "name": "라면, 조리전",
    "matchMethod": "NORMALIZED_RULE",
    "confidence": 0.84
  }
}
```

프론트는 영양값뿐 아니라 품질과 국가표준 연결 근거를 함께 표시할 수 있습니다.

## 12. 검토가 필요한 부분

- 복합 상품은 하나의 대표 표준식품으로 단순화됩니다.
- 용량이 없는 상품은 실제 포장 단위가 아닌 100g 또는 100ml 기준입니다.
- 음료는 g과 ml의 밀도 차이를 별도로 계산하지 않습니다.
- 낮은 신뢰도의 분류 기본값은 실제 제품과 차이가 날 수 있습니다.
- 품목제조보고번호 자동 확정은 포장지 확인을 대신하지 않습니다.
- 공식 서비스 사용 전에는 영양 전문가가 대표 식품 연결과 목표 기준을 검토해야 합니다.
